POG、DeepFashion、U-NEED、SHIFT15M 等都存在许可或图片版权约束。若模型最终面向门店生产环境，公开数据更适合做预训练、架构验证和离线评测；真正决定上线效果的仍应是自有商品、搭配、导购对话和成交反馈数据。

### POG 的实际获取提示

POG目前仍是最值得优先下载验证的数据，但建议预先做好以下准备：

1. 先下载三个结构化压缩包，再根据 pic\_url 批量抓取仍有效的图片。

2. 为每张图片保存下载时间、原URL、HTTP状态、哈希和本地路径。

3. 预期会有图片失效、403、防盗链、商品下架和内容被替换。

4. cate\_id 只有数字ID，官方发布内容里没有完整、可解释的中文类目字典，需要自行抽样映射。

5. 用户数据属于匿名点击序列，并不等于购买、满意或搭配偏好；训练时应区分 item click、outfit click 和强转化信号。

6. 由于没有明确数据许可证，建议将POG训练产物标记为“研究用途模型”，不要直接并入商业模型主干。

## 二、更值得补充的数据集

### 1. 中文售前导购与对话式推荐：U-NEED

U-NEED官方仓库比JDDC更贴近你们的导购任务：

* 7,698段细粒度标注的真实售前对话；

* 333,879条用户行为；

* 332,148条商品知识三元组；

* 包含 Fashion 和 Shoes 两个直接相关品类；

* 逐句标注说话动作、涉及属性以及推荐商品；

* 支持需求理解、需求追问、商品推荐、对话生成和评估。

获取不是直接下载：按照官方申请说明，需向 baohua.dbh@alibaba-inc.com 发邮件，提供姓名、单位、研究方向、岗位、申请原因和邮箱。条款明确限定研究学习、禁止商业使用，并要求研究结束后删除。

建议优先级：高。 在“导购意图识别、需求槽位抽取、何时追问、何时推荐”等方面，它明显比JDDC合适。

### 2. 大规模穿搭与时间分布：SHIFT15M

SHIFT15M来自日本时尚服务IQON，约覆盖1500万件商品，支持穿搭集合建模、set-to-set matching、价格/热度预测和时间分布漂移研究。

可直接安装或下载：

```
pip install shift15m
git clone https://github.com/st-tech/zozo-shift15m.git
cd zozo-shift15m
bash scripts/download_all.sh
```

优点是规模大、包含套装、价格、发布时间、标签、点赞数等，比Polyvore更适合研究季节变化和趋势漂移。缺点是日文/日本市场、不是中国门店场景，而且数据采用 CC BY-NC 4.0，禁止商业使用。下载及许可证说明

### 3. Fashionpedia

Fashionpedia官方仓库提供直接的S3下载链接，包含：

* 27个服装主类别；

* 19个服装部件；

* 294个细粒度属性；

* 实例分割mask及局部属性；

* COCO兼容的JSON标注。

它比DeepFashion2更适合构建“可解释属性标签体系”，例如领型、袖型、长度、材质观感和局部设计。适合预训练检测＋属性识别，再映射到自有中文商品属性字典。商用前仍需逐项检查图片级license字段。

### 4. iMaterialist Fashion Attribute

iMaterialist Fashion Attribute官方入口是百万级多标签服装属性数据，适合：

* 商品图片多标签分类；

* 长尾属性识别；

* 视觉编码器预训练；

* 从商品图自动补齐结构化标签。

它在“细粒度属性分类”方面通常比DeepFashion2更对口，但同样需要审查竞赛数据条款以及底层图片版权。

### 5. FACAD / Fashion Captioning Dataset

FACAD官方项目主要用于服装图片描述，价值在于将视觉属性组织成自然语言，而不是只输出标签。可以帮助训练：

* “这件衣服是什么风格”的中文描述；

* 导购侧商品卖点生成；

* 图片属性到自然语言的桥接。

如果将来希望模型不仅识别“方领、泡泡袖”，还会说“方领能够突出颈部线条”，FACAD类数据比纯分类数据更有帮助。但公开下载和许可情况需要以仓库当前说明为准，不能只依据引用论文。

### 6. CSDS：中文客服对话摘要

CSDS官方仓库提供百度网盘和Google Drive下载，是中文客服对话摘要数据，带整体摘要、用户摘要、客服摘要和主题片段。

它不适合学习服装推荐，但适合训练：

* 长对话需求摘要；

* 将多轮交流压缩成顾客画像或导购交接记录；

* 提取顾客问题、偏好和已推荐方案。

## 三、推荐的数据组合

如果目标是训练一个真正可用的服装导购与推荐系统，我建议不要把这些数据混成一个大SFT语料，而是按任务分层：

| 模型能力      | 公共数据起点                                  | 必须补充的自有数据                  |
| :-------- | :-------------------------------------- | :------------------------- |
| 图片自动打标签   | Fashionpedia、iMaterialist、DeepFashion/2 | 自有SKU图片＋中文属性字典＋人工复核标签      |
| 找同款/相似款   | DeepFashion2、Fashion200K                | 门店商品图库、上下架状态、库存和价格         |
| 根据文字修改结果  | FashionIQ、Fashion200K                   | 中文“更宽松一点/正式一点/不要太显肩”等真实改选对 |
| 搭配兼容性     | Polyvore Disjoint、POG、SHIFT15M          | 中国顾客和门店商品的成套搭配、导购认可/否决数据   |
| 个性化排序     | POG                                     | 曝光、点击、试穿、收藏、加购、成交、退货及时间戳   |
| 售前需求理解    | U-NEED Fashion/Shoes                    | 自有导购对话、顾客属性、场景、预算和禁忌       |
| 客服语言及对话摘要 | JDDC、CSDS                               | 品牌话术、真实政策、门店服务流程           |
| 最终回复生成    | 公共对话只做弱预训练                              | 自有高质量导购示范＋知识库＋安全规则         |

## 四、几个需要修正的认识

1. POG虽是中文电商数据，但并不是可以无条件商用的中文训练集。 它最重要的资产是用户—商品—穿搭关系，而不是中文标题本身。

2. FashionIQ/Fashion200K不是严格意义上的真实多轮反馈数据。 FashionIQ有人工相对描述和对话式设定；Fashion200K的修改文本大量由商品描述差异自动构造。它们适合组合检索，不适合直接训练完整导购对话策略。

3. DeepFashion2没有丰富的通用商品属性标签。 它强在检测、分割、关键点、遮挡和shop-consumer同款配对。若目标是自动补齐领型、图案、材质、风格等字段，应将Fashionpedia、iMaterialist或DeepFashion Attribute Prediction一起纳入。

4. JDDC并不天然代表优秀导购话术。 真实客服语料会包含模板回复、售后争议、平台政策、低质量表达和过时流程。如果直接SFT，可能让模型过度客服化、频繁致歉或生成错误政策。更适合做中文电商语言适配、查询改写和摘要，不应作为搭配推荐主数据。

5. 公开时尚数据普遍存在图片版权与许可错位。 GitHub代码许可证只约束代码，不一定覆盖从电商网站抓取的商品图片、标题和描述。

## 五、落地优先顺序

建议按下面顺序推进：

1. 立即下载并审计 POG、FashionIQ、Fashion200K、Fashionpedia。

2. 申请 U-NEED、DeepFashion/DeepFashion2、JDDC 2.x。

3. 用 Polyvore Disjoint＋POG 完成兼容性模型基准。

4. 用 FashionIQ＋自建中文修改指令集完成 REQUEST\_ALTERNATIVE 检索。

5. 用 Fashionpedia/iMaterialist 预训练属性模型，再用自有SKU做中文标签微调。

6. 尽早建立自有“曝光—推荐—试穿—改选—成交—退货”链路；这是任何公开数据集都无法替代的生产数据。

7. 商业上线前建立数据权利清单：数据来源、许可文本、允许用途、图片权利、保留期限、是否允许衍生模型、联系人和审批证据。
